# История Desktop: что пришлось исправлять

## Брендинг без смены интерфейса

Задача начиналась с собственного имени, прозрачного облачного логотипа icon2-clear,
цветов и адреса сервера. Игровой icon1 не использовался. Логотипы упакованы в SVG
и PNG; в исходниках оставлены лицензии и правообладатели Nextcloud.
Папка с пользовательской синхронизацией не использовалась для clone/build.

После первого запуска пользователь подтвердил работу приложения.
Затем доработаны ссылки в мастере, help/conflict/about, Client Push и welcome-тексте.
Юридические уведомления и внутренние протокольные имена не переименовывались вслепую.

## Explorer: важная регрессия

Исходная очистка namespace считала своей и запись с именем Nextcloud.
У брендированного клиента это затронуло запись оригинального приложения.
Запись восстановили. Проверка ownsNamespaceEntry теперь принимает только имя
текущего приложения; отдельный NavigationPaneHelperTest покрывает чужие записи.
Тест воспроизвёл отказ до исправления, после него прошёл.
Сравнение реестра при запуске подтвердило сохранность восстановленной записи.
Данные синхронизации при этом не удалялись.

## Трей и проверяемый результат

Первые значки показывали в основном зелёный статус, а пользователь хотел видеть бренд.
Подготовлены шесть SVG с облачным знаком и badges состояний. Theme::themeIcon
выбирает брендовые варианты для трея. Тесты проверяют прозрачность, сохранность
фирменных цветов, состояния и монохромную настройку; одного успешного compile было недостаточно.

## Самостоятельный пакет

Локальный запуск через Craft ещё не означал переносимость EXE.
Упаковщик собирает Qt/QML/plugins, переводы, DLL, CfAPI runtime и лицензии.
NSIS использует список принадлежащих пакету файлов, сохраняет посторонние данные
и просит закрыть занятое приложение. Проверены отдельная установка/удаление,
сохранность чужого файла и запуск с чистым PATH на предыдущем пакете.
На пакете с новым доменом повторены хеши и clean-environment startup.

## Смена домена 28 октября

Default заменён с DuckDNS на cloud.mshostcloud.org; версии и интерфейс не менялись.
Нужно было обновить CMake CACHE явным -DAPPLICATION_SERVER_URL.
После успешных CMake/link/tests проверка упакованной DLL всё ещё нашла старый URL:
зависимости от config.h не заставили пересобраться три старых объекта.
Их удалили из build и собрали заново. В окончательной DLL подтверждён новый адрес,
старый домен в библиотеках продукта отсутствовал.

## Очистка и границы проверки

После первой упаковки очищены 6,16 ГиБ временных файлов/кэшей. Исходники,
установленные инструменты, пакеты и пользовательские данные сохранены.
Две короткие рабочие ссылки Craft в D:\_ оставлены: перестановка каталогов
с абсолютными путями может сломать сборку.

Полный live-вход, синхронизация, virtual files и обновление поверх каждой прежней
версии не выводятся из результата ThemeTest или запуска окна --version.
Подробности серверного перехода вынесены в [отдельную запись](server-migration.md).
